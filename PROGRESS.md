- **Развёрнут на сервере:** Ubuntu, `195.209.213.51`, домен `discopok.fun` → порт 8000 (пока без TLS), запуск
  `scripts/server_up.sh` (`.env.prod` со случайными секретами лежит только на сервере — не терять). Проверено:
  `/health` → `environment: prod`, Redis и Postgres подключены; боты (`bot_client.py --host discopok.fun:8000`) и клиент
  с эмулятора сыграли раздачи. Скрипт проверен и локально в Docker: регистрация переживает рестарт api.
- **Следующее:** Caddy перед api (Let's Encrypt для `discopok.fun`, клиент на `https`/`wss`, порт 8000 закрыть снаружи);
  возврат фишек при остановке (ниже) — до регулярных обновлений сервера.

**Известные проблемы:**
- **Остановка сервера теряет фишки на столах.** `Table.stop()` выходит из цикла (`__stop__` в `table.py`), стеки на баланс
  не возвращаются, а бай-ин уже списан. В k8s под перезапускается при каждом деплое — чинить до выкладки.
- Без Redis счётчик колод локальный и после рестарта начинается с 1 — раздачи идут по тем же колодам в том же порядке.
- При одновременном `quick_join` ботов один может уехать на второй стол (гонка в `registry`).
- `make lint` — 44 старых замечания ruff (новые строки чистые).
- Сервер, запущенный без `--reload`, после правок перезапускать руками; в памяти столы и аккаунты пропадают.

## План: контейнер и k8s

Состояние живёт в памяти процесса (`registry._tables`, `accounts._accounts`, `SessionStore._current`, `hub._by_player`),
поэтому несколько реплик сейчас ломают игру. По этапам:

0. **Одна реплика.** Возврат фишек при остановке; образ — `.dockerignore`, не root, один процесс uvicorn.
   k8s: `Deployment` с `replicas: 1` и `strategy: Recreate` (RollingUpdate на минуту даст две копии столов),
   `terminationGracePeriodSeconds` ≈ 60, `Ingress` с длинным таймаутом WebSocket, секреты в `Secret`.
   Postgres и Redis — управляемые. Домен + TLS (cert-manager), клиент ходит на `wss://`.
1. **Подготовка к нескольким подам.** Баланс — атомарный `UPDATE … WHERE balance >= :x` в Postgres без кэша в памяти;
   `SessionStore` в Redis.
2. **Несколько подов.** Стол живёт на одном поде: `StatefulSet`, в Redis `table_id → под`, лобби/`quick_join` отдаёт
   клиенту WS-адрес пода, Ingress маршрутизирует по пути. Альтернатива — команды стола между подами через Redis pub/sub.
