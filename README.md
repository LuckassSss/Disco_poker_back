# Neon Poker — бэкенд

Серверная часть онлайн-покера для тонкого Unity-клиента.
**No-Limit Texas Hold'em, кэш-игра, 5 мест за столом, столов — сколько угодно.**

Клиент не знает правил и не хранит карт: он открывает WebSocket, показывает
то, что прислал сервер, и отправляет ходы. Вся логика, все карты и весь банк
живут на сервере.

## Что уже работает

* WebSocket-сервер на FastAPI, один сокет на игрока
* Полные правила NLHE: блайнды, четыре улицы, мин-рейз, олл-ины, сайд-поты,
  сплиты с нечётными фишками, возврат неколированной ставки
* **Автоподбор стола** (`quick_join`): сервер сам сажает в стол со свободным
  местом, а если такого нет — создаёт новый
* Три уровня ставок (микро / низкие / средние), настраиваются в конфиге
* **10 заранее замешанных колод**, выдача по глобальной очереди в Redis —
  в рантайме случайные числа не генерируются вообще
* Таймер хода и авто-фолд, сит-аут после серии авто-фолдов
* Реконнект: место держится за игроком, при возврате приходит полный снимок стола
* Гостевая авторизация (JWT) — заглушка с узким интерфейсом под будущие аккаунты;
  токен живёт 30 суток и служит ключом от аккаунта, продление — по старому токену
* PostgreSQL (игроки, балансы, опционально история раздач) и Redis
* 52 теста ядра, включая марафон на 1000+ раздач с проверкой инвариантов

## Быстрый старт

**С Docker** — поднимает сервер, Postgres и Redis:

```bash
docker compose up --build
```

**Без Docker** — скрипт сам создаст окружение и поставит зависимости:

```bash
./scripts/run_local.sh
```

Проверить, что сервер жив, и посмотреть на игру:

```bash
curl localhost:8000/health

# в другом окне: пять ботов садятся за стол и играют
python3 scripts/bot_client.py --bots 4 --hands 20 --stake low
```

Боту не нужны ни виртуальное окружение, ни установленные пакеты — он работает
на голом `python3` (3.11+). Четыре бота, а не пять, чтобы за столом осталось
свободное место для вашего клиента.

Адреса: HTTP `http://localhost:8000`, WebSocket `ws://localhost:8000/ws?token=<JWT>`,
интерактивная документация API `http://localhost:8000/docs`.

Токен для подключения:

```bash
curl -sX POST localhost:8000/auth/guest \
     -H 'Content-Type: application/json' \
     -d '{"nickname":"Женя"}'
```

Postgres и Redis не обязательны для того, чтобы просто поиграть: если их нет,
сервер напишет предупреждение и продолжит работать на памяти (счётчик колод
станет локальным).

### Почему стол — актор

Каждый стол живёт в своей `asyncio`-задаче с очередью команд. Всё, что меняет
состояние стола — ход игрока, срабатывание таймера, отключение, посадка —
попадает в эту очередь и обрабатывается по одному. Поэтому в коде стола нет
ни одной блокировки, и гонок вида «игрок сходил ровно в момент таймаута»
не может возникнуть в принципе.

Игровое ядро (`app/core/`) при этом полностью синхронное и ничего не знает про
сеть: раздачу можно прогнать в тесте за микросекунды, что и делает марафон
на 1000 раздач.

## Заранее замешанные колоды

Требование проекта — никакой генерации случайных чисел во время игры.

* `data/decks.json` содержит 10 колод. Они сгенерированы один раз скриптом
  `scripts/generate_decks.py` детерминированным Fisher–Yates, где источник
  «случайности» — поток SHA-256 от фиксированного сида. Файл воспроизводим
  байт в байт: перегенерируйте с тем же сидом и сверьте (это проверяется тестом).
* Сервер только читает файл и раздаёт колоды **по кругу**: `INCR` глобального
  ключа в Redis → `deck_id = (номер - 1) % 10`. Счётчик один на все столы и все
  инстансы сервера, поэтому две раздачи, начавшиеся подряд, гарантированно
  получат разные колоды.
* Каждая раздача несёт `deck_id` и `deck_sequence` — по ним её можно повторить
  и проверить постфактум.

Увеличить число вариантов на порядок:

```bash
python scripts/generate_decks.py --count 100
docker compose restart api
```

Формат файла и алгоритм не меняются, код трогать не нужно.

> **Важно понимать про безопасность.** Фиксированный набор колод — это
> сознательный выбор ради воспроизводимости, но он же означает, что игрок,
> увидевший 10 раздач, знает все возможные колоды, а зная позицию счётчика,
> может предсказать следующую. Для игры на реальные деньги этого мало: там
> нужен криптографически стойкий шафл на раздачу плюс commit-reveal
> (сервер публикует хеш колоды до раздачи и саму колоду после).
> Точка расширения уже готова: `DeckProvider.next_deck()` — единственное место,
> где решается, какая колода пойдёт в игру. Эндпоинт `/decks` намеренно отдаёт
> только контрольные суммы, а не карты.

## Уровни ставок

| Код | Блайнды | Бай-ин |
|---|---|---|
| `micro` | 1 / 2 | 80 – 200 |
| `low` | 5 / 10 | 400 – 1000 |
| `mid` | 25 / 50 | 2000 – 5000 |

Задаются в `app/config.py` (`DEFAULT_STAKES`). Клиент шлёт
`quick_join {"stake": "low"}`, автоподбор ищет стол внутри уровня и берёт
самый заполненный из тех, где есть место — так столы доукомплектовываются,
а не размазывают игроков по десятку полупустых.

## Протокол

Полный справочник — [docs/PROTOCOL.md](docs/PROTOCOL.md). Коротко:

```
POST /auth/guest {"nickname": "Женя"}  ->  {"token": "...", "player_id": "..."}
ws://host:8000/ws?token=<token>

-> {"t": "quick_join", "d": {"stake": "low"}}
<- {"t": "joined_table", "d": {снимок стола}}
<- {"t": "hand_started", ...}
<- {"t": "hole_cards", "d": {"cards": ["Ah","Kd"]}}     только вам
<- {"t": "action_required", "d": {"options": [...], "time_limit": 20}}
-> {"t": "action", "d": {"action": "raise", "amount": 120}}
<- {"t": "player_action", ...} {"t": "street", ...} {"t": "hand_finished", ...}
```

`amount` в ставках — суммарная ставка «до» на этой улице, а не приращение.
Считать минимальный рейз клиенту не нужно: допустимые границы всегда приходят
в `options`.

## Тесты

```bash
pytest                    # если установлены dev-зависимости
python tests/run_all.py   # тот же набор без pytest
```

Что покрыто:

* `test_hand_eval` — все категории комбинаций, колесо A-2-3-4-5, кикеры, равные руки
* `test_pot` — сайд-поты, возврат неколированной ставки, нечётные фишки,
  инвариант «сколько вложили — столько раздали»
* `test_deck_provider` — валидность файла колод, воспроизводимость генерации,
  выдача строго по кругу без пропусков
* `test_game_flow` — очередь хода в 5-max и хедз-апе, опция большого блайнда,
  рост минимального рейза, неполный олл-ин не открывает торговлю заново,
  сайд-пот в реальной раздаче, сплит
* `test_simulation` — 1900+ раздач ботами на 2, 3 и 6 игроков, включая прогоны
  на микро- и перекошенных стеках, с проверкой инвариантов на каждой раздаче:
  фишки не появляются из воздуха и не пропадают, карты не дублируются,
  стеки не уходят в минус, раздача всегда завершается
* `test_ws_client` — встроенный WebSocket-клиент: кодек кадров сверяется
  с контрольными примерами из RFC 6455, плюс полный прогон по настоящему
  сокету (рукопожатие, маскировка, длинные и фрагментированные кадры, ping)
* `test_bot_end_to_end` — неизменённый `bot_client.py` играет по настоящему
  сокету против настоящего игрового стека
* `test_integration_table` — прогон всего сервисного слоя: реестр, автоподбор,
  актор стола с настоящими таймерами, хаб соединений, счета. Подменён только
  транспорт: вместо WebSocket объект с `send_json`/`close`. Проверяются посадка
  шести ботов за один стол, сохранность фишек, авто-фолд по таймауту, реконнект
  с восстановлением состояния и то, что чужие карманные карты не утекают

## Что дальше

Ближайшее по важности:

1. **Настоящая авторизация** — сейчас гостевой JWT; интерфейс в
   `app/auth/tokens.py` менять не придётся.
2. **Горизонтальное масштабирование.** Сейчас стол живёт в памяти процесса.
   Redis уже подключён; следующий шаг — регистр `table_id → инстанс` и роутинг
   сокета на нужный инстанс (или sticky-сессии на балансировщике).
3. **Рейк** — точка вставки одна: `HandEngine._finish`, перед распределением банков.
4. **Античит и наблюдаемость** — история раздач уже пишется при
   `PERSIST_HAND_HISTORY=true`, дальше метрики Prometheus и детект сговора.
5. **Турниры** — растущие блайнды, выбывание, балансировка столов. Ядро к этому
   готово: `HandEngine` ничего не знает про формат стола.
